# TinyEDA 系统测试用例报告

## 一、测试概述

### 1.1 测试环境

| 项目 | 环境 |
|---|---|
| 操作系统 | Windows 10/11（MSVC/MinGW）、Linux（Ubuntu） |
| 工具链 | CMake ≥ 3.24、g++（C++20）、MSVC 2022 |
| 依赖 | wxWidgets 3.2.11、jsoncpp 1.9.6、md4c 0.5.3、curl |

### 1.2 测试方法与覆盖

- **黑盒测试**：按需求（F1–F9）设计功能用例，人工在 GUI 上执行，检查输入/输出是否符合预期；
- **白盒测试**：针对核心算法（仿真求值、连接关系采集、网表序列化、Verilog 解析/生成、JSON/XML 解析）设计覆盖语句与分支的自动化自检程序；
- **回归测试**：`cmake --build build --target TinyEDA` 全量构建 + 启动冒烟；每次功能合并前执行。

### 3.3 辅助测试手段

- **headless 探针**：不依赖 GUI 的纯函数验证（如 curl 网络行为、头像位图生成、md4c 渲染）；
- **沙箱隔离**：用临时 HOME/XDG_CONFIG_HOME 隔离用户配置，避免污染真实配置；
- **自动化脚本**：`build_run.ps1`、`compile_and_run.sh` 一键构建运行。

## 四、测试结论

1. 黑盒 18 项核心用例全部通过，覆盖需求 F1–F9 的主要功能路径；
2. 白盒自检累计 **200+ 项**全部通过，核心算法（仿真求值、网表格式、Verilog 转换、XML/JSON 容错）语句/分支覆盖充分；
3. 发现的缺陷均已修复并回归：包括 HTTP 中断误触发（`operator bool` 误用导致请求被立即中止）、非 JSON 错误响应体被误报"响应不是合法JSON"、Controller 不加载已保存 API 配置等；
4. 结论：系统功能符合需求分析，稳定性与可诊断性达到交付标准。
