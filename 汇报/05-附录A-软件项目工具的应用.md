# 附录A：软件项目工具的应用

> 本附录单独记录项目开发过程中使用的工具、对编写代码的管理方式，以及测试方法/过程工具的学习和使用情况。

## 一、版本管理工具：Git

### 1.1 使用情况

| 用途 | 具体做法 |
|---|---|
| 分支管理 | 按功能建分支：`main`（主干）、`verilator` / `verilator-v2`（Verilog 转换）、`feat/agent`（AI 助手）、`simulation`（仿真）；各自独立开发后**定期合并回主干** |
| 并行开发 | 多人/多分支并行推进，通过 merge 记录整合（如 `Merge remote-tracking branch 'origin/main' into feat/agent`、`第一次 合并main和verilator`） |
| 提交规范 | 提交信息概括功能点（如"仿真：开关按两端导通建模"、"Agent 工具增强、配置保存修复"）；仓库累计 62 个提交 |
| 冲突处理 | 拉取队友更新后若 CMakeLists 冲突，先 `git diff` 弄清改动再合并，不直接丢弃本地改动 |

### 1.2 常用命令记录

```bash
git branch feat/agent          # 新建功能分支
git checkout feat/agent        # 切换分支
git add <文件> ; git commit    # 提交
git pull --rebase              # 拉取并变基
git merge <分支> / git diff    # 合并 / 查看差异
git log --oneline              # 提交历史
```

### 1.3 学习收获

- 学会了用"功能分支 + 定期合并"避免主干不稳定，理解了合并冲突的成因（同一文件并行修改）与解决流程；
- 认识到**分支是并行开发的协作手段**：仿真、Verilog、AI 三个方向在各自分支上互不阻塞。

## 二、构建与依赖管理：CMake + FetchContent

| 工具 | 应用 |
|---|---|
| CMake | 替代 Visual Studio 工程，`cmake -S . -B build` 配置 + `cmake --build build --target TinyEDA` 编译；Windows（MSVC/MinGW）与 Linux 同一套流程 |
| FetchContent | 自动拉取 wxWidgets 3.2.11、jsoncpp 1.9.6、md4c 0.5.3；Windows 下额外静态编译 curl（TLS 用 Schannel） |
| GLOB + CONFIGURE_DEPENDS | `file(GLOB_RECURSE SOURCES CONFIGURE_DEPENDS "src/*.cpp")` 自动收录新增源文件，简化"新增文件要改工程文件"的负担 |
| 平台差异处理 | `add_executable(... WIN32 ...)`、MSVC `/utf-8`、链接 `wx::xml`/`wx::html` 组件、`localtime_r` 兼容宏等（详见 README） |

## 三、测试工具与方法

| 工具/方法 | 使用记录 |
|---|---|
| 自检程序（白盒） | tests/ 下 8 个独立可执行自检程序，覆盖 XML/网表/仿真/Verilog 桥/元数据，累计 200+ 项断言 |
| 黑盒人工测试 | 按需求用例逐项在 GUI 操作验证（见《04-测试用例报告.md》） |
| headless 探针 | 无 GUI 环境下验证纯逻辑：curl 网络行为（401/中断）、头像位图生成、md4c Markdown 渲染、设置配置回读 |
| 环境隔离 | 用临时 HOME/XDG_CONFIG_HOME 隔离用户配置，避免测试污染真实配置（wxStandardPaths 默认用 $HOME 而非 XDG_CONFIG_HOME 的坑已记录） |
| 一键脚本 | `build_run.ps1` / `compile_and_run.sh` 简化构建运行；`run_TinyEDA.bat` 自动补齐第三方 DLL 与工作目录 |

## 四、AI 辅助工具的使用

| 用途 | 说明 |
|---|---|
| 代码辅助 | 使用大模型辅助排查疑难 bug（如 C++ `std::function` 布尔上下文误调 `operator bool()` 导致请求被中断的隐蔽问题、wx 事件宏约束、跨平台编译错误） |
| 测试辅助 | 生成/维护自检程序与 headless 探针，验证修复效果 |
| 项目自身产物 | 项目内置的 Agent 功能正是把"AI 辅助设计电路"作为产品能力，与团队使用 AI 工具辅助开发形成呼应 |

## 五、工具应用小结

| 阶段 | 工具 | 解决的问题 |
|---|---|---|
| 开发前 | 规划文档 + Git 分支 | 明确目标、避免冲突、并行开发 |
| 编码 | CMake / FetchContent / 编辑器 CMake Tools | 跨平台构建、依赖管理、快速编译运行 |
| 测试 | 自检程序 / 探针 / 黑盒用例 | 算法正确性、GUI 功能、网络异常场景 |
| 协作 | Git 合并 / README 活文档 | 多人并行、交接与复现 |
