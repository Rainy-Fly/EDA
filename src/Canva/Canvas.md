# Canvas区域的任务
## 大纲
这是一个小型EDA项目，我负责其中一个子区域Canvas的开发。
实现鼠标滚轮缩放Canvas画布，元件的点击,放置，移动；元件元数据的初始化，位置的控制
以下的详细说明
## 画布移动
Canvas会保持一个内部的逻辑坐标系，Canvas画布在实际的窗口中不变，但是在逻辑坐标系中会变。而元件附着在这个逻辑坐标系coords网格中，
Canvas画布窗口就像一个摄像机，他逻辑移动时，元件的coords虽然不变，但是在画布窗口上的pos会改变
以下是两种改变情况
### 中键滚动
鼠标在屏幕的pos不变，画布的逻辑坐标改变，刷新元件显示大小和画布的逻辑坐标（offset_coords）
### 按住中键滑动
拖动画布在逻辑坐标系中移动，元件的窗口pos跟着变

## 额外内容
ToolBar（元件调色板），放在主窗口左侧栏、资源树上方（类似 Logisim 左边的元件列表），里面有基础元件：与非门，与门，或门，或非门，异或门，非门，导线，仿真用的**输入端子/输出端子**（小方框：输入端子单击切换 0/1、输出端子显示所接网络电平），以及动作工具：选择/删除/克隆。界面上只有 16px 图标，名字放在悬停提示里：元件用 src/Canva/assets/Symbols/ 或 src/assets/electronic-symbols/SVG/ 的符号当图标，导线/选择/删除/克隆用 src/Canva/assets/Tools/ 的小图标；Windows 下要往 exe 里嵌 comctl32 v6 清单（src/TinyEDA.rc），否则按钮图标显示不出来。
把src/Canva/assets/Symbols/下的图片对应CanvasItem。当CanvasItem被初始化时，构造函数使它持有对图片的引用（来自 ItemSVG 共享缓存，不拥有）。图片引用不变，而放大缩小时由画布按 scale 重绘成位图（update_bitmap），位图由画布 onPaint 统一绘制 —— 元件不再持有子窗口，透明底才不会变成灰块。
鼠标点击ToolBar的按钮后（按下即生效），如果是门，那么就有虚影跟随鼠标，鼠标点击Canva后实例化在点击位置；之后单击已放置的元件即可让它跟随鼠标移动、再单击放下（按住拖动也仍然可以）。
点击导线后，先不做处理，以后再说.
## 仿真显示（画布自绘，类似 Logisim）
- 导线按电平着色：**1 = 亮绿粗线（带淡绿外发光）**、0 = 中灰粗线、X/未知 = 蓝、未参与仿真 = 深灰细线。
  0 特意不用深绿：深绿和亮绿肉眼难分，容易被误读成"已经变 1 了"。
- 元件状态画在**第二遍覆盖层**里（`draw_state_overlay`）：等所有位图都画完再画，
  这样相邻元件的位图不会把徽标盖掉。内容：端子方框内的 0/1/X、门的输出徽标、灯亮时的黄色光晕、不参与仿真元件的灰色 ✕。
- 单击"输入开关/输入端子"（左键按下后没有拖动）切换 0/1，写进实例参数 `State`（随项目保存）；按住拖动仍然是移动元件。
- 画布只从主窗口注入的 `Simulation::SimulationSession` 里读值，不自己算逻辑；
  内容变化通过 `set_simulation_dirty_callback` 通知主窗口去重建。
ItemPNG.hpp:传入元件名字，调用读取配置的函数（具体怎么读先不实现）返回CanvasItem里对应的类型的引用。由于现在我们还没有准备好图片，因此没有时不报错.
